# Agent Note: 输入框文件引用——`@`-文件菜单与回形针文件选择按钮

Status: implemented

[English](2026-08-15-composer-file-references.md) | 中文

> 范围：向 Web 输入框插入会话工作区文件的纯文本 `@rel` 引用——`@`-文件触发源与 `conversation.input.left` 选择器——基于新的有界宿主文件浏览器（`host.listFiles` / `host.listLevel` / `ctx.fileBrowser`）。目录行参与两个表面：`@` 菜单列出文件夹（尾部斜杠 + 文件夹字形），选择器是可展开的目录树并带路径编辑器，可以跳到任意目录，因此工作区根目录之外的行以绝对宿主路径引用。不在范围：带出现身份的"文件 chip"、把文件内容注入模型上下文、`@路径` 词元的草稿装饰，以及选择器在光标处插入。

## Problem

在 Web 输入框里引用工作区文件意味着凭记忆手打精确的相对路径，GUI 没有任何选择器：`@` 触发源只注册了子智能体，browse 目录列举只返回目录（是目录选择器而非文件浏览器），附件入口只收图片。宿主侧根本没有文件列举原语——线上表面止步于 browse 能力下的 `host.listDirectory`，而 native 目录选择器部署甚至不挂载它。

## Decision

**新宿主缝：`ctx.fileBrowser`（dsh-host-file-browser），有界递归列举与单层列举。** `host.listFiles({path})` 通过 Node 标准库对根做广度优先遍历，返回 `{name, rel, path, kind}` 行（`kind` 为 `file` 或 `directory`），`rel` 为相对根、正斜杠分隔的拼写（即输入框引用形式），并遵循经校验的 Config 边界：`maxFiles`（默认 500）、`maxDirs`（默认 200）、`maxDepth`（默认 6）、`skipDirs`（默认 `node_modules`/`.git`）、`skipHidden`（默认 true）。符号链接一律跳过（无环、无逃逸）；广度优先顺序保证截断结果保留最浅层行；每个文件系统 await 都与调用方的 `AbortSignal` 竞速。`host.listLevel({path})` 返回单层目录内容（文件与目录，按名称排序，同一套跳过规则，受 `maxFiles` 约束），让选择器的树按文件夹展开逐层加载，而不是每次点击都重扫工作区。失败映射到既有的 `directory-unreadable` 线上错误码。缝=服务定义 + 同一包内的唯一已交付 provider（目前看不到第二个后端）；消费方是网关 resolver，沿用 directory-picker 缝的形状。web-app bundle 无条件挂载该行——它与任一目录选择器后端无关，因为 native 选择器部署同样需要文件引用。

**浏览器表面是一个插件：dsh-client-ui-file-reference。** 两个入口共享同一份列举缓存（按会话、30 秒 TTL、并发去重、失败不缓存）：

- `@`-文件源注册进 ui-input-trigger 管线（`trigger: '@'`，`name: 'file'`，排在子智能体分组之上）。候选为按路径或基名不区分大小写过滤后的列举；目录行以尾部斜杠 + 文件夹字形拼写，让菜单能区分文件夹与文件；无工作区会话或列举失败给出空组。选中返回纯文本引用 `@rel `——尾部空格闭合触发词元，与子智能体源一致；无出现、无 codec（plain-text-reference 决策）。
- 回形针文件选择按钮占据 `conversation.input.left` 槽位：弹窗把工作区当作目录树浏览——工作区根目录是初始基准，文件夹行就地展开/收起，每一层都经 `host.listLevel` 懒加载（不可读的文件夹回退为收起态并显示行内提示、下次点击重试），路径编辑器把基准跳到任意完全限定目录（工作区根目录按钮可返回），过滤框按名称收窄可见行并保留命中项所在的祖先文件夹。确认时把 `@rel1 @rel2` 追加到草稿末尾，经会话输入面（`conversation.input.for(actx)`——同一同步回合内读快照并 `setDraft`，一次机器事务、一步撤销）；工作区根目录之下的行插入其绝对宿主路径。输入处于非 plain 阶段时按钮禁用；无工作区、不可读、截断、空结果各有说明性表面。

**模型契约就是字面路径。** 每选中一个引用，用户提示词中增加普通文本 `@<路径>`——会话根目录之下为相对路径，在根目录之外的目录中选取时为绝对路径；模型把它解析为自己的工作目录（绝对形式则对照宿主文件系统）下的路径，用自己的文件工具读取。请求的其他部分不变，也没有新增提示词段落——该引用是自解释的散文，不同于需要显式引导的 deliverables 提及语法。

## Alternatives considered

- **客户端用 `host.listDirectory` 遍历**——browse RPC 只列目录，且在 native 选择器组合（回环桌面端的默认形态）下不存在；文件源不能依赖它。
- **扩展 directory-picker browse 能力加入文件列举**——该能力是目录选择专用的按种类判别联合；给输入框的文件列举是另一个关注点，且部署与选择器种类无关，因此拥有自己的缝。
- **文件引用用带出现身份的 U+FFFC chip**——纯文本决策已用于技能/子智能体引用；文件并不需要 chip 才有的东西，chip 只会为零模型收益引入 codec/序列化工作。
- **把文件内容注入模型上下文**——那是另一个量级的结构化引用功能（会话事件、token 记账、日志重建）；纯字面量推迟它而不排除它。
- **新增提示词段落告诉模型 `@rel` 的含义**——子智能体引用至今没有消费语义也能工作；路径提及是自解释的。引导只会增加需要钉住的模型可见表面。

## Consequences

- Web GUI 现在可以用两次点击引用会话工作区下的任何文件（通过路径编辑器也可以引用其他目录中的文件），且引用就是模型看到的同一文本。宿主列举有界且可取消，深层或巨大的工作区每个会话每 30 秒窗口最多花一次有界遍历，另加每次展开文件夹的一次有界单层读取。
- 选择器在草稿末尾追加（非光标处），`@路径` 词元没有草稿装饰（文本引用扫描只匹配单词形名称），层级按展开加载（弹窗打开期间新建的文件需重新展开才出现），工作区之外的引用是绝对宿主路径。这些已记入插件 README 的 Known Limitations。
- 模型可见表面：只有字面引用文本——无新会话事件、无提示词段落、无工具注册。
- 测试：单元 spec 覆盖遍历边界/跳过/中止、单层原语、缓存语义、源契约（含 HMR 安全卸载）与树弹窗状态（展开/收起、重试、路径跳转、绝对引用）；无密钥组装 Web e2e（`apps/web/tests/file-references.e2e.ts`）通过已交付组合驱动真实宿主文件浏览器，播种工作区树与一个外部兄弟目录，并钉住提交的提示词原样携带引用。
