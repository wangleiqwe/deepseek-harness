# Agent Note: composer file references — the '@' file menu and the file-picker button

Status: implemented

English | [中文](2026-08-15-composer-file-references.zh.md)

> Scope: inserting plain-text `@rel` references to files under the session workspace into the Web composer — the `@`-file trigger source and the `conversation.input.left` picker — over a new bounded host file browser (`host.listFiles` / `host.listLevel` / `ctx.fileBrowser`). Directory rows participate in both surfaces: the `@` menu lists folders (trailing slash + folder glyph), and the picker is an expandable directory tree with a path editor that jumps to any directory, so rows outside the workspace root reference by absolute host path. Not in scope: file chips with occurrence identity, content injection into the model context, draft decoration of `@路径` tokens, and caret-position insertion for the picker.

## Problem

Referencing a workspace file from the Web composer meant typing its exact relative path from memory, and the GUI offered no picker for it: the `@` trigger registered only subagents, the browse directory listing served directories only (a directory picker, not a file browser), and the attach affordance accepted images only. The host side had no file-listing primitive at all — the wire surface stopped at `host.listDirectory` under the browse capability, which the native directory-picker deployments do not even mount.

## Decision

**A new host seam: `ctx.fileBrowser` (dsh-host-file-browser) with bounded recursive and one-level listings.** `host.listFiles({path})` walks the root breadth-first through Node's stdlib, returns `{name, rel, path, kind}` rows (`kind` is `file` or `directory`) with forward-slash root-relative `rel` spellings (the composer reference form), and honors validated Config bounds: `maxFiles` (default 500), `maxDirs` (default 200), `maxDepth` (default 6), `skipDirs` (default `node_modules`/`.git`), and `skipHidden` (default true). Symlinks are skipped entirely (no cycles, no escapes); the breadth-first order keeps a truncated result's shallowest rows; every filesystem await races the caller's `AbortSignal`. `host.listLevel({path})` returns one directory level (files and directories, name-sorted, the same skip rules, `maxFiles`-bounded) so the picker's tree loads per folder expand instead of re-walking the workspace per click. Failures map to the existing `directory-unreadable` wire code. The seam is definition + the single shipped provider in one package (no second backend is foreseeable); the consumers are the gateway resolvers, following the directory-picker seam's shape. The web-app bundle composes the row unconditionally — it is not tied to either directory-picker backend, because the native picker deployments still need file references.

**The browser surface is one plugin: dsh-client-ui-file-reference.** Two affordances over the same listing cache (per-session, 30s TTL, in-flight coalescing, failures uncached):

- The `@`-file source registers into the ui-input-trigger pipeline (`trigger: '@'`, `name: 'file'`, ordered above the subagent group). Candidates are the listing filtered case-insensitively by path or base name; directory rows are spelled with a trailing slash and a folder glyph so the menu tells folders from files; a workspace-less session or a failed listing yields an empty group. Pick returns the plain-text reference `@rel ` — trailing space closes the trigger token, mirroring the subagent source; no occurrence, no codec (the plain-text-reference decision).
- The file-picker button occupies the `conversation.input.left` seat (paperclip glyph): a modal browsing the workspace as a directory tree — the workspace root is the initial base, folder rows expand and collapse in place with each level lazy-loaded through `host.listLevel` (an unreadable folder reverts to collapsed with an inline hint and retries on the next click), a path editor jumps the base to any fully qualified directory (the workspace-root button returns), and a filter narrows the visible rows keeping ancestor folders of matches. Confirm appends `@rel1 @rel2` to the end of the draft through the conversation input face (`conversation.input.for(actx)` — read snapshot and `setDraft` in the same synchronous turn, one machine transaction, one undo step); rows below the workspace root insert their absolute host path. The button disables outside the plain input phase and shows explanatory surfaces for no-workspace, unreadable, truncated, and empty states.

**The model contract is the literal path.** A pick adds `@<path>` to the user's prompt as ordinary text — workspace-relative under the session root, absolute when picked from a directory outside it; the model resolves it against its working directory (or the host filesystem for absolute forms) with its own file tools. Nothing else about the request changes, and no prompt-section guidance was added — the reference is self-explanatory prose, unlike the deliverables mention syntax which needed explicit guidance.

## Alternatives considered

- **Walking `host.listDirectory` client-side** — the browse RPC lists directories only and is absent under the native picker composition (the shipping default on loopback desktops); a file source cannot depend on it.
- **Extending the directory-picker browse capability with a file listing** — the capability is a per-kind discriminated union owned by directory selection; file listing for the composer is a different concern with a kind-independent deployment, so it gets its own seam.
- **U+FFFC chips with occurrence identity for file references** — the plain-text decision already exists for skill/subagent references; files add nothing chips would need, and chips would force codec/serialization work for zero model benefit.
- **Injecting file contents into the model context** — a structured-reference feature of a different magnitude (session events, token accounting, log reconstruction); the plain literal defers it without foreclosing it.
- **A prompt-section telling the model what `@rel` means** — the subagent reference still has no consumption semantics and works; a path mention is self-explanatory. Guidance would only add model-visible surface to pin.

## Consequences

- The web GUI can now reference any file under the session workspace (and, via the path editor, any file in another directory) with two clicks, and the reference is the same text the model sees. The host listings are bounded and cancellable, so a deep or huge workspace costs at most one bounded walk per 30s window per session plus one bounded level read per folder expand.
- The picker appends at the end of the draft (not the caret), `@路径` tokens get no draft decoration (the text-ref scan matches word-ish names only), levels appear as they load (files created while the modal is open appear on re-expand), and outside-workspace references are absolute host paths. These are recorded Known Limitations in the plugin README.
- Model-visible surface: the literal reference text only — no new session events, no prompt sections, no tool registrations.
- Testing: unit specs cover the walk bounds/skips/abort, the level primitive, the cache semantics, the source contract (incl. HMR-safe disposal), and the tree modal states (expand/collapse, retry, path jump, absolute refs); the keyless assembled-web e2e (`apps/web/tests/file-references.e2e.ts`) drives the real host file browser through the shipped composition, seeds a workspace tree plus an outside sibling directory, and pins that the submitted prompt carries the references verbatim.
